# Что вы присылаете и что получаете

**От вас до начала работ**

| Данные | Комментарий |
|---|---|
| Юридическое наименование и БИН | - |
| Контактное лицо: ФИО, email, телефон | Канал передачи секрета и эскалаций |
| Адрес мини-апки для prod и для stage | HTTPS. Может содержать свой фрагмент - SPA-роут вида `#/catalog` сохранится |
| Название (KK/RU/EN) и логотип для карточки | Отображение в разделе «Сервисы» |

**От нас**

| Что | Комментарий |
|---|---|
| `app_id` мини-апки | UUID. Публичный идентификатор |
| Секрет мини-апки | Передаётся один раз по защищённому каналу. Повторно то же значение не выдаётся |

**По отдельному согласованию**

Часть данных и методов открывается правом. Право закрепляется за вашей мини-апкой при подключении, его коды приезжают в поле `scope` [контекста запуска](/launch-context).

| Право | Что открывает |
|---|---|
| `phone:read` | Метод моста [`getPhone`](/bridge/get-phone) - номер абонента. Это контактные данные, а не идентификатор: учётная запись у вас заводится по `user.id` из контекста |

## Окружения

Адрес мини-апки для `staging` и для `production` заводится отдельно. У каждого окружения свой `app_id` и свой секрет: контекст, подписанный для `staging`, на `production` не проходит.

Для разработки нужен постоянный `https`-адрес: свой тестовый домен или туннель с фиксированным именем до локальной машины - [постоянный адрес для разработки](/debugging#постоянныи-адрес-для-разработки). Адрес регистрируется один раз и меняется только через менеджера, поэтому быстрый туннель со случайным именем при каждом запуске не подходит. Регистрируйте адрес вместе с путём, по которому отдаётся мини-апка: приложение открывает ровно то, что зарегистрировано.

Изменения адреса применяются с задержкой до 60 секунд.
