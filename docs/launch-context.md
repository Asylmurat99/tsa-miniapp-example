# Контекст запуска

Мы открываем ваш адрес, добавив во фрагмент один параметр - `tsaWebAppData`:

```
https://miniapp.example.kz/#tsaWebAppData=app_id%3D34d5810c-7c36-11eb-82e7-f2189812cd57%26auth%3Dcustomer%26auth_date%3D1755388800%26nonce%3D7c9e6679-7425-40de-944b-e07fc1f90ae7%26platform%3Dios%26start_param%3Dchannels%26user%3D%257B%2522id%2522%253A%25223f1a9c40-77ad-4e0f-9c3d-11c2a0f5e881%2522%257D%26hash%3D72408ed73eebbc71d35b750b683eabdd8825916925350e7eb5ffb67e3ca74f12
```

Его значение - **вся строка контекста целиком**, закодированная процентами. Декодируете один раз и получаете обычную query-string:

```
app_id=34d5810c-7c36-11eb-82e7-f2189812cd57&auth=customer&auth_date=1755388800&nonce=7c9e6679-7425-40de-944b-e07fc1f90ae7&platform=ios&start_param=channels&user=%7B%22id%22%3A%223f1a9c40-77ad-4e0f-9c3d-11c2a0f5e881%22%7D&hash=72408ed73eebbc71d35b750b683eabdd8825916925350e7eb5ffb67e3ca74f12
```

Если у вашего адреса уже есть фрагмент, он сохраняется, а параметр добавляется через `&`: `https://miniapp.example.kz/#/catalog&tsaWebAppData=...`.

**Та же строка лежит в `window.tsaWebApp.initData`** - приложение кладёт её туда до загрузки вашего кода. Берите контекст оттуда: фрагмент теряется при переходах и перезагрузке. Свойство есть только в главном фрейме - в iframe контекста нет.

::: danger Содержимое контекста не логировать
Не отправляйте контекст в логи, аналитику и сторонние сервисы: в нём идентификатор абонента и действующая подпись.
:::

| Поле | Что означает |
|---|---|
| `app_id` | Ваша мини-апка |
| `auth` | Вид запуска: `customer` - пришёл абонент, `guest` - пользователь не авторизован в приложении. Присутствует всегда |
| `auth_date` | Unix-время выдачи, сек |
| `nonce` | Случайное значение, своё на каждый запуск |
| `platform` | `ios` или `android` |
| `scope` | Коды выданных вам [прав](/onboarding), через запятую. Серверные права сюда не попадают никогда. Отсутствует, пока прав не выдано |
| `start_param` | Какой экран открыть, если карточка его задавала. **Параметр навигации.** Значение приходит от клиентского приложения и нами не проверяется - не связывайте с ним доступ, скидку или промо. Может отсутствовать |
| `user` | JSON-объект `{"id":"<uuid>"}`. `id` - идентификатор абонента **для вашей мини-апки**, стабилен навсегда: тот же пользователь всегда приходит с тем же значением. Используйте его как ключ учётной записи у себя; номер телефона из [`getPhone`](/bridge/get-phone) на эту роль не годится, он может измениться. **Отсутствует при `auth = guest`** |
| `hash` | [Подпись](/verify) остальных полей |

Состав полей ограничен этой таблицей.

**`user` в подпись идёт декодированным** - ровно как есть, `{"id":"<uuid>"}`, один ключ, без пробелов. Не пересобирайте JSON заново: другой порядок ключей или лишний пробел дадут другие байты и несошедшуюся подпись.

## Что делает мини-апка

Весь код мини-апки, который знает про приложение, - один файл. Остальное общается только с собственным бэкендом.

- `readInitData` - берёт строку контекста. Сначала `window.tsaWebApp.initData`, и только если свойства нет - `tsaWebAppData` из фрагмента, оттуда оно придёт уже декодированным. Пустая строка означает, что страницу открыли вне приложения.
- `stripFragment` - убирает `tsaWebAppData` из адресной строки и возвращает на место остаток фрагмента: там ваш роут. Остаток вырезается построчно, а не через `URLSearchParams.toString()`: тот дописывает `=` ключу без значения и превратит `#/catalog` в `#/catalog=`.
- `inShell` - `bridge.isSupported()`, то есть «страница открыта внутри приложения». В обычном браузере любой вызов моста заканчивается ошибкой.
- `requestPhone` - запрашивает [конверт с номером](/bridge/get-phone) и разводит исходы по коду ошибки.

Строка контекста уходит на бэкенд как есть, одним телом запроса. Разбор на клиенте не нужен и вреден: подпись посчитана по этим самым байтам.

::: warning initDataUnsafe
Рядом лежит `window.tsaWebApp.initDataUnsafe` - разобранный объект, в котором есть только `user`, `auth_date`, `start_param`, `platform` и `hash`. Поля `auth` в нём нет, поэтому отличить гостя по нему нельзя. Подпись по нему не проверяется. Годится, чтобы отрисовать экран до ответа вашего бэкенда, и больше ни для чего - решения о доступе принимаются по проверенному контексту.
:::

## Что делает бэкенд

1. Разобрать строку как query-string штатным парсером - он декодирует значения, включая `user`.
2. Проверить `hash` по [алгоритму проверки](/verify) своим секретом. Не сошлась - отказать.
3. Проверить, что `auth_date` отличается от вашего текущего времени не больше чем на 300 секунд **в любую сторону**. Вне окна - отказать, попросить пользователя переоткрыть мини-апку.
4. Ветвиться по `auth`: для `customer` - найти или создать учётную запись по `user.id`. Ключ учётной записи - именно он, а не номер телефона: номер у абонента может смениться, `user.id` - нет.

**Повтор контекста.** `nonce` уникален на каждый запуск, и по нему можно отсекать повторное предъявление перехваченного контекста. Это рекомендация, не требование: окно `auth_date` уже ограничивает жизнь контекста шестьюстами секундами, а реестр предъявленных значений требует общего хранилища между экземплярами вашего бэкенда. Заводите его, если сам запуск мини-апки открывает платное действие или доступ к деньгам. Тогда храните предъявленные `nonce` не менее 900 секунд: интервал приёма `[T−300, T+300]` - 600 секунд, и хранилище короче него пропустит повтор в конце окна.

Разбор шага 4 - на странице [абонент и гость](/customer-and-guest).
