# Системные действия

Методы, которыми мини-апка отдаёт данные наружу - в системное меню, в буфер обмена и во внешний браузер, - и три метода про само приложение: язык, биометрия и настройки.

## share

```ts
share: (text: string) => Promise<ActionResponse>
```

Открывает системное меню «Поделиться» с текстом. Куда именно уйдёт текст, выбирает пользователь - приложение этого не знает и вам не сообщает.

```js
await bridge.share('Мой заказ №1024: https://miniapp.example.kz/orders/1024');
```

## copyToClipboard

```ts
copyToClipboard: (text: string) => Promise<ActionResponse>
```

Кладёт текст в системный буфер обмена. Системного уведомления о копировании нет - показывайте своё.

```js
await bridge.copyToClipboard('KZ123456789012345678');
```

## openExternalUrl

```ts
openExternalUrl: (url: string) => Promise<ActionResponse>
```

Открывает ссылку во внешнем браузере, за пределами контейнера мини-апки. Мини-апка при этом остаётся открытой.

```js
await bridge.openExternalUrl('https://example.kz/terms');
```

Контекст запуска во внешний браузер не переносится: страница, открытая так, о пользователе ничего не знает.

## getLanguage

```ts
getLanguage: () => Promise<GetLanguageResponse>
```

Возвращает язык интерфейса приложения и список языков, которые оно поддерживает:

```json
{ "language": "ru", "supported": ["ru", "kk", "en"] }
```

Контекст запуска языка не несёт, поэтому первый экран стоит рисовать по этому ответу. Свой переключатель языка, если он есть, держите поверх: выбор пользователя внутри мини-апки важнее языка приложения. Так делает пример: [`hostLanguage`](/launch-context) в `web/src/tsa.ts`.

```js
const { language } = await bridge.getLanguage();
```

Парный `setLanguage` мини-апке отвечает `PERMISSION_DENIED`: язык приложения принадлежит приложению.

## checkBiometry

```ts
checkBiometry: () => Promise<BiometryResponse> // 'success' | 'unavailable' | 'cancelled'
```

Показывает системный диалог биометрии и сообщает, чем он закончился: `success` - пользователь подтвердил, `cancelled` - отказался или не прошёл, `unavailable` - на устройстве биометрии нет или она не настроена.

```js
if (await bridge.checkBiometry() === 'success') showSensitiveScreen();
```

::: warning Результат ничего не доказывает вашему бэкенду
Ответ приходит на страницу и дальше никуда не передаётся; страница может отправить бэкенду любое значение. Годится, чтобы закрыть экран от постороннего, взявшего телефон в руки, и не годится для подтверждения операций. Подтверждённые данные о пользователе - только [контекст запуска](/launch-context) и [`getPhone`](/bridge/get-phone).
:::

## openSettings

```ts
openSettings: () => Promise<ActionResponse>
```

Открывает системную страницу настроек приложения Telecom - ту, где пользователь управляет его разрешениями. Отвечает `"success"`, если страница открылась, и `"not_implemented"`, если система не дала её открыть. Настройки самой мини-апки там не появятся: это экран приложения, а не ваш.

```js
await bridge.openSettings();
```
