# pushSend

Серверный метод (S2S), не метод моста: его вызывает бэкенд вашей мини-апки напрямую, в обход веб-страницы и `tsa`-моста. Требует право `push:send`.

```
POST https://{env}-gateway.telecom.kz/api/v1/partner/push_send
```

::: warning Это вызов сервер-сервер
Метод не имеет отношения к `tsa.*` - его не вызывают со страницы мини-апки. Запрос собирает, подписывает и шлёт ваш бэкенд тем же секретом, что вы уже используете для проверки [контекста запуска](/launch-context).
:::

## Тело запроса

```json
{
  "app_id": "34d5810c-7c36-11eb-82e7-f2189812cd57",
  "route": "push_send",
  "partner_user_id": "3f1a9c40-77ad-4e0f-9c3d-11c2a0f5e881",
  "timestamp": 1756715400,
  "nonce": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "title": "Заказ готов",
  "message": "Можно забирать из пункта выдачи",
  "start_param": "order-42"
}
```

| Поле | Обяз. | Что означает |
|---|---|---|
| `app_id` | да | Ваша мини-апка |
| `route` | да | Всегда `push_send` |
| `partner_user_id` | да | `user.id` из [контекста запуска](/launch-context) - тот же абонент, для которого мини-апка открывалась |
| `timestamp` | да | Unix-время отправки, окно ±300 секунд |
| `nonce` | да | Своё на каждый вызов - повтор отклоняется |
| `title` | да | 1-50 символов, без управляющих символов |
| `message` | да | 1-280 символов, перевод строки - единственный допустимый управляющий символ |
| `start_param` | нет | `[A-Za-z0-9_-]{1,64}` - попадёт в контекст запуска, если абонент откроет мини-апку из уведомления |

## Подпись

```
X-Signature: v1=<hex(HMAC-SHA256(тело как есть, ваш секрет))>
```

HMAC считается по сырым байтам тела - тем самым, что уходят по сети, без повторной сериализации JSON. Секрет тот же, что вы уже используете для проверки конвертов контекста запуска.

## Пример вызова

```bash
BODY='{"app_id":"34d5810c-7c36-11eb-82e7-f2189812cd57","route":"push_send","partner_user_id":"3f1a9c40-77ad-4e0f-9c3d-11c2a0f5e881","timestamp":1756715400,"nonce":"7c9e6679-7425-40de-944b-e07fc1f90ae7","title":"Заказ готов","message":"Можно забирать из пункта выдачи","start_param":"order-42"}'
SIGN=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | sed 's/^.* //')

curl -X POST "https://staging-gateway.telecom.kz/api/v1/partner/push_send" \
  -H 'Content-Type: application/json' \
  -H "X-Signature: v1=$SIGN" \
  -d "$BODY"
```

## Ответ

```json
{ "status": "accepted" }
```

Успешный ответ значит только, что уведомление зарегистрировано у нас - доставка асинхронная, статус доставки вам не возвращается и не хранится на нашей стороне.

::: danger Лимит - 10 пушей в сутки на пару мини-апка+абонент
Отсчёт идёт с первого пуша этой мини-апки этому абоненту за последние 24 часа. При исчерпании - `429` с заголовком `Retry-After`.
:::

## Исходы вызова

| Исход | HTTP | Код ошибки | Что делать |
|---|---|---|---|
| Принято | 200 | - | Уведомление зарегистрировано, доставка асинхронная |
| Мини-апка не найдена или отключена | 401 | `invalid_app` | Проверьте `app_id` |
| Подпись не сошлась | 401 | `invalid_sign` | Проверьте секрет и что подписываете именно эти байты тела |
| Вызов не с разрешённого адреса | 403 | `ip_not_allowed` | Сообщите нам исходящий IP вашего бэкенда |
| Право `push:send` не выдано | 403 | `insufficient_scope` | Обратитесь к нам за грантом |
| Абонент не открывал вашу мини-апку под этим `user.id` | 404 | `unknown_user` | Отправить пуш можно только тому, кто хотя бы раз получал [контекст запуска](/launch-context) |
| Абонент есть, но пуш доставить некуда | 404 | `upstream_not_found` | Штатный исход, не ошибка - у абонента нет активного устройства |
| Тело не прошло валидацию | 422 | `validation_error` | Проверьте пределы `title` / `message` / `start_param` |
| Квота исчерпана | 429 | `rate_limited` | Повторить после `Retry-After` |
| Не дождались доставки | 504 | `upstream_timeout` | Повторить с новым `nonce` |
| Сбой на нашей стороне | 500 | `internal_error` | Повторить позже |

Тело ошибки - `{ "code": "...", "message": "..." }`, как и у остальных методов.

::: warning `unknown_user` и `upstream_not_found` - разные отказы
Оба похожи на «абонента нет», но означают разное. `unknown_user` - мы вообще не знаем такого `partner_user_id` для вашей мини-апки: он ни разу не открывал её через [контекст запуска](/launch-context). `upstream_not_found` - абонента мы знаем, но у него нет устройства, куда доставить пуш. Разделяйте эти случаи в логике повторов: первый ретраем не решить.
:::
