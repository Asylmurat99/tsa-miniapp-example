# Как это работает

Ваш веб-сервис открывается в мобильном приложении Казахтелекома по карточке в разделе «Сервисы». Отдельный логин пользователю не нужен: при открытии мы передаём подписанный контекст, из которого ваш бэкенд узнаёт, кто пришёл. Если пользователь сам не авторизован в приложении, контекст всё равно придёт — без данных о нём: [абонент и гость](/customer-and-guest).

Всё держится на одном секрете мини-апки: им подписываем мы, вы проверяете. По сети секрет не передаётся никогда.

## Шесть шагов запуска

1. Пользователь тапает по карточке мини-апки в разделе «Сервисы».
2. Приложение открывает ваш адрес и добавляет во фрагмент подписанный [контекст запуска](/launch-context).
3. Мини-апка читает контекст из `window.tsaWebApp.initData`.
4. Мини-апка убирает контекст из адресной строки, оставив на месте свой роут.
5. Мини-апка передаёт строку контекста своему бэкенду как есть, не разбирая её.
6. Ваш бэкенд проверяет подпись и `auth_date`, поднимает свою сессию.

## Кто → кому → что

| Кто | Кому | Что |
|---|---|---|
| Пользователь | Приложение | Тап по карточке |
| Приложение | Мини-апка | Адрес с контекстом запуска во фрагменте |
| Мини-апка | Мини-апка | Чтение контекста, очистка фрагмента |
| Мини-апка | Ваш бэкенд | Строка контекста целиком |
| Ваш бэкенд | Ваш бэкенд | Проверка подписи и `auth_date` |
| Ваш бэкенд | Мини-апка | Своя сессия |

Дальше мини-апка работает со своим бэкендом как обычный веб-сервис. К приложению она обращается только за тем, чего в вебе нет, — через [методы моста](/bridge/).
